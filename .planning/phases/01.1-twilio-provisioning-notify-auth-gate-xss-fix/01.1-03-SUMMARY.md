# Phase 01.1 Plan 03: WhatsApp Singleton Race Fix Summary

**One-liner:** Race-safe WhatsApp singleton using cached `__whatsappInitPromise` on `globalThis` with `whenReady()` API and explicit fail-loud guard for missing `PUPPETEER_EXECUTABLE_PATH`.

## What Was Built

### Race Condition Fix (T-01.1-09)
Concurrent cold-start requests to the WhatsApp API routes previously triggered multiple `initClient()` calls simultaneously, spawning duplicate Puppeteer/Chromium instances. The fix:

1. Added `__whatsappInitPromise: Promise<Client> | undefined` to `globalThis` declarations
2. `whenReady()` checks this cached promise before creating a new one — all concurrent callers `await` the same promise
3. `getWhatsAppClient()` also routes through the cached promise for backward compat

### Hardcoded Path Removal (T-01.1-10)
The `|| '/Users/mahekpatel/.cache/puppeteer/...'` fallback silently used a developer machine path in production. Replaced with:
- Explicit check: if `PUPPETEER_EXECUTABLE_PATH` is unset, throw with a clear actionable error message pointing to `/usr/bin/google-chrome-stable` on VPS

### Retry/Reconnect Safety
Both error paths (`disconnected` event and `client.initialize().catch`) now clear `__whatsappInitPromise = undefined`, allowing the next call to `whenReady()` to retry initialization cleanly.
