# Phase 01.1: Security Hardening + Twilio Removal - Context

**Gathered:** 2026-04-12
**Status:** Ready for planning

<domain>
## Phase Boundary

Phase 01.1 hardens the notification stack for wedding-day production use. It removes the dead Twilio/SMS channel, gates all sensitive API routes behind auth, fixes the email XSS surface, adds server-side dedup cooldown, and fixes the WhatsApp singleton init race. After this phase, the app is safe to run on the public Hetzner VPS without risk of abuse.

**Final architecture confirmed by user:** 2 channels only — Email (Gmail SMTP on port 587) + WhatsApp (whatsapp-web.js group post + individual DMs). No SMS.

**Hosting:** Hetzner VPS (Ashburn, VA) — NOT Vercel. whatsapp-web.js + Puppeteer runs as a persistent process via pm2. Domain: photos.mikemetsaumone.com with Certbot SSL.

</domain>

<decisions>
## Implementation Decisions

### Channel Architecture
- Drop Twilio entirely — remove `twilio` package from package.json, remove all TWILIO_* env var references, remove SMS code paths from /api/notify/route.ts, remove SMS-related fields from NotificationResponse type
- Final channels: (1) Email per-member via Nodemailer/Gmail SMTP port 587 (2) WhatsApp group post + per-member DMs via whatsapp-web.js
- Correct 01-03 SUMMARY inaccuracy: SMS was claimed removed but was re-introduced in commit 6dfc61d. Update SUMMARY to reflect the real history.

### Auth Gate (CR-02 from 01-REVIEW.md)
- Create a `requireAuth()` helper (lib/require-auth.ts or inline) that validates the same Base64 `wedding_auth` token the dashboard uses
- Wire it into: /api/notify, /api/whatsapp-status, /api/whatsapp-groups, /api/test-notify, /api/test-whatsapp-cloud
- Client callers in app/page.tsx (handleNotify, handleBulkNotify) must send Authorization: Bearer ${localStorage.getItem('wedding_auth')} header
- Return 401 with { success: false, message: 'Unauthorized' } on failure

### Email XSS Fix (CR-01 from 01-REVIEW.md)
- Create an escapeHtml() helper for member.name interpolation in HTML email body
- Apply to all ${member.name} interpolations in the HTML template (both first-notify and resend variants)
- Plaintext email body does not need escaping (not rendered as HTML)

### Server-Side Dedup Cooldown (WR-06 from 01-REVIEW.md)
- Replace client-supplied lastNotifiedAt cooldown with a server-side module-level Map<number, number> keyed by groupNumber
- Reject with 429 if Date.now() - lastSend < 60_000
- This is safe on Hetzner VPS (long-running process, Map persists across requests)
- Remove the client-side lastNotifiedAt from the request body (or ignore it) — server is the authority

### WhatsApp Singleton Init Race Fix (CR-04 from 01-REVIEW.md)
- Cache the initialization promise (not just the client) in globalThis
- Expose a whenReady() async helper that callers await before sending
- Update /api/notify and /api/whatsapp-status to use whenReady() instead of getWhatsAppClient() + status check

### Chromium Path Cleanup (CR-03 code-level from 01-REVIEW.md)
- Remove the hardcoded /Users/mahekpatel/.cache/puppeteer/... fallback from lib/whatsapp-session.ts
- Fail loudly with a clear error if PUPPETEER_EXECUTABLE_PATH is not set
- On the VPS, PUPPETEER_EXECUTABLE_PATH=/usr/bin/google-chrome-stable is already in .env.local

### Claude's Discretion
- Implementation details of the escapeHtml function (standard & < > " ' replacement)
- Whether requireAuth reads token from Authorization header vs cookie (header is preferred per existing dashboard pattern)
- Whether to keep the test routes (/api/test-notify, /api/test-whatsapp-cloud) behind TEST_MODE gate in addition to auth gate, or auth gate only

</decisions>
