# Phase 01.1 Plan 02: Notify Route Overhaul Summary

**One-liner:** Notification route overhauled — auth-gated with requireAuth(), all Twilio/SMS code removed, escapeHtml on HTML email bodies, server-side dedup Map with anySuccess guard, WhatsApp calls use race-safe whenReady(), twilio package uninstalled.

## What Was Built

### app/api/notify/route.ts — complete overhaul

**Auth gate (T-01.1-04):**
`requireAuth(request)` is the very first operation in the POST handler. Returns 401 immediately if the Authorization: Bearer token is missing or invalid. No notification logic executes for unauthenticated requests.

**Twilio/SMS removal (T-01.1-08):**
- Removed `import twilio from 'twilio'`
- Removed `twilioClient` initialization block
- Removed `messageText()` function (was SMS-only)
- Removed entire "Send SMS via Twilio" block in the per-member loop
- Removed `smsStatus` variable and all references
- Removed SMS simulation log line from test mode
- `whatsappDmStatus` initialized to `'skipped'` (will be updated by WhatsApp DM block)

**XSS fix (T-01.1-05):**
`escapeHtml(member.name)` applied in both HTML email templates (resend and first-notify). Plaintext email bodies use `${member.name}` directly (correct — no HTML injection risk in text).

**Server-side dedup (T-01.1-06 + T-01.1-07):**
- Module-level `lastSentMap = new Map<number, number>()` with `COOLDOWN_MS = 60_000`
- `isResend = lastSentMap.has(groupNumber)` — determined before cooldown check, correct for variant selection after cooldown expires
- Cooldown rejects with 429 and exact wait seconds if `lastSent && Date.now() - lastSent < COOLDOWN_MS`
- `lastSentMap.set(groupNumber, Date.now())` called ONLY after `anySuccess === true` — failed sends do not start the cooldown timer

**WhatsApp group post — whenReady() (T-01.1-09):**
Replaced `getWhatsAppStatus()` status check + `getWhatsAppClient()` pattern with:
```typescript
const client = await whenReady();
await client.sendMessage(whatsappGroupId, whatsappGroupMessage);
```
Wrapped in try-catch; sets `whatsappGroupStatus = 'failed'` on error.

**WhatsApp individual DMs — whenReady():**
Replaced `waStatus === 'ready'` guard + `getWhatsAppClient()` with `whenReady()` outer try-catch. Inner per-member try-catch updates `memberResult.whatsappDmStatus` to `'sent'` or `'failed'` in the results array.

**anySuccess check — no SMS references:**
```typescript
const anySuccess = response.results!.some(
  (r) => r.emailStatus === 'sent' || r.emailStatus === 'simulated-success' ||
         r.whatsappDmStatus === 'sent' || r.whatsappDmStatus === 'simulated-success'
);
```

**Response message:**
`Sent to ${members.length} member(s): ${emailCount} emails, ${dmCount} WhatsApp DMs`

### lib/whatsapp-session.ts — whenReady() added

The worktree had the pre-Plan-03 version of this file. Applied Plan 03 changes:
- Added `__whatsappInitPromise: Promise<Client> | undefined` to globalThis declarations
- `initClient()` now returns `Promise<Client>` resolving on `ready` event
- `whenReady()` exported — checks `__whatsappInitPromise` before creating new one (race-safe)
- Removed hardcoded `/Users/mahekpatel/.cache/puppeteer/...` path; fail-loud guard: throws if `PUPPETEER_EXECUTABLE_PATH` unset
- `disconnected` and `initialize().catch` handlers clear `__whatsappInitPromise` to allow retry
- `getWhatsAppClient()` and `getWhatsAppStatus()` retained for backward compatibility

### package.json — twilio removed

`npm uninstall twilio` removed `twilio ^5.13.1` from dependencies. No file in the codebase imports from `'twilio'`.
